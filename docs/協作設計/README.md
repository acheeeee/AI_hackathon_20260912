## 3. 與舊文件的關係

本套文件針對「人工協作、側邊欄、修改提案、版本與 API」承接並細化使用者最新決策；此範圍與[北極星指南手冊](../北極星指南手冊.md) v1 不一致時，以本套為準。命題要求、法律考證與其餘功能範圍仍依原文件；本次未重新認證任何法律判斷。

| 舊設計 | 本次補充／取代 |
|---|---|
| 「轉人工佇列」沒有後續操作 | 在原案件原畫面註記、查證與覆核，再由後端重算分流 |
| 黃燈禁止草稿，混合紅黃優先序不清 | 區分可討論／可編輯的工作內容與可採用／可送審的結果，詳見 01 |
| 第 3、8 款永遠回待人工 | 機器原結果保留；人工有獨立覆核結果，兩者並列，不假裝 AI 自行解除 |
| 重新生成直接更新草稿 | 完整候選版本＋三方 diff＋明確採用；保留人工修改 |
| 只有簡單 `/api/cases/...` 端點清單 | 使用 04 的 `/api/v1` 契約，舊端點僅是遷移來源 |
| 範例日期有民國字串、來源為自由文字 | API 日期統一西元 ISO；來源使用前處理規格的結構化 spans |

## 5. 第一批需交付的共同契約

1. 同一組 `case_id`、`case_revision`、`resource_revision`、`run_id`、`proposal_id`。
2. 同一組選取範圍與 source ref，不用前端 DOM 座標猜文件位置。
3. 同一份「修改日期→重算→diff→採用」與「選一句話→改寫→採用」範例。
4. 已採用修改、未採用提案、聊天與查詢紀錄各自可辨識。

實作進度一律在 05 記為 `NOT RUN/PASS/FAIL`；文件存在不代表能力已完成。
