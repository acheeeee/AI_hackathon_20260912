## 遇到不一致時

1. 已驗證的「實作現況」看 sysdoc、程式碼與本次測試；不能用設計文字宣稱已完成。
2. 人工協作、側邊欄、修改提案、版本與 API 的「目標設計」以 `協作設計/` 為準。
3. 資料來源、引用座標、schema、評估分組及品質門檻以交接規格為準。
4. 法律命題與考證回到 `Reference/開發文件.md` 及其原始來源；本次整理不重新認證法律正確性。

本次保留既有設計文件的原路徑，只新增閱讀入口、修正過期路徑與現況提示，避免移動後產生第二套互相矛盾的規格。
